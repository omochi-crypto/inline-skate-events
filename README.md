# 全国インラインスケート大会情報

全国のインラインスケート大会を収集し、人が承認した大会だけをWebサイトに掲載します。
スピード（トラック・ロード）、マラソン・ウルトラ、地方団体・クラブ、その他競技の順に収集・確認を優先します。

## 普段の使い方

1. 毎日10:25（日本時間）のActionsで収集します。手動実行もできます。
2. 新しい今後の大会だけが `[大会候補]` Issueになります。過去大会は収集検証用データに残り、公開しません。
3. 所有者が公式情報とIssueのJSONを照合します。必要なら大会名、日付、都道府県、公式URLなどを修正します。
4. 内容を修正した場合は `/preview` とコメントすると、新しい承認コードと形式検証結果が表示されます。
5. **人間の所有者が** `/approve <承認コード>` をコメントすると、承認記録とともに `events/approved.json` に登録され、公開Actionsが実行されます。

ラベル変更やIssueを閉じるだけでは公開しません。bot、所有者以外、古い承認コード、開催済み大会、不正なURL、不足項目は拒否します。再承認・内容変更は自動上書きしません。
Actionsの「Approve reviewed inline event」の手動実行は**検証専用**で、公開は行いません。

## 公開先とLINE

GitHub Pagesを「GitHub Actions」方式で有効にした場合のURL：
https://omochi-crypto.github.io/inline-skate-events/

LINE Official Account Managerのリッチメニューで、アクション種類「リンク」に上記URLを設定してください。
LINEへの送信やLINEログインは必要ありません。スマートフォンで種目・都道府県・大会名を絞り込めます。
本リポジトリにLINEのアクセストークンを保存する必要はありません。

## 件数とエラーの確認

収集ActionsのSummaryに以下を表示します。

- 抽出件数・一意件数・収集元間の重複件数
- 今後の大会・開催済み大会の件数
- Issueの新規件数・既存重複・次回繰越
- 収集元ごとの取得成否・日付不明などの要確認件数

Artifacts `collection-report-<run_id>` に全候補JSON、`collection.json`、Summaryを90日保存します。
取得エラーはActionsを失敗にし、`[収集監視]` Issueに記録します。次回正常取得時に復旧コメントを残して閉じます。
閉じた大会Issueも重複判定に使い、履歴を削除しません。

初期版からIDの計算方法を変更したため、移行直後に旧IDと新IDの同一大会Issueが1回ずつ存在する場合があります。新IDは収集元に依存せず、大会名（表記正規化）と開催日で安定します。大会名が大きく異なる別名表記は自動統合しません。

## 収集範囲と限界

`events/sources.json` が実行対象です。WSJ公式の一覧・年間予定表、岐阜県協会、地域クラブ、伊丹の公式要項PDFを対象としています。
全国すべての団体・SNSを網羅したものではありません。画像だけの告知、日付未定、月だけの記載、非連続開催日は推測せず警告に残します。
ブログの開催年を記事年から補う場合は候補に注記し、人間による確認を必要とします。開催済み大会を翌年に繰り上げて扱いません。
地方の未対応サイト・取得制限・旧ドメインの状況は `events/regional-source-watchlist.json` に記録します。

収集元には同時アクセス3件、25秒のタイムアウト、1回の再試行、HTML/PDFサイズ上限を設けています。
抽出断片は要確認の証拠として候補にのみ保存します。公開用データに自動転送しません。

## 開発と検証

```sh
pip install -r requirements.txt
python -m unittest discover -s tests -v
python scripts/collect_events.py
python scripts/build_site.py
python -m http.server 8000 --directory public
```

公開ビルドは承認者・承認コメントID・内容のハッシュを検証し、候補ファイルをコピーしません。
人間の承認でデータが変更された場合だけ、承認Actionsから再利用可能な公開ワークフローを呼び出します。`GITHUB_TOKEN` によるコミットが通常のpushイベントを発火しない場合でも公開を進められます。`/preview` では公開処理を起動しません。

## 安全上の作業範囲

変更対象は `omochi-crypto/inline-skate-events` のみです。天気予報用の別リポジトリは変更しません。
実在大会の承認をテストとして代行しません。承認経路の正例は隔離した一時ファイル、実Issueでは公開しない `/preview` を使って検証します。
