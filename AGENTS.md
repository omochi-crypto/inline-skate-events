# Repository scope

Work only in omochi-crypto/inline-skate-events. Never modify the separate weather repository.

Fix collection, Actions, reporting and website problems autonomously within reasonable bounds. Run meaningful regression tests and inspect Actions logs after changes. Preserve Issue and commit history. Never delete historical Issues or force-push.

Human final approval is mandatory before an event is published. The user has authorized a chat-based yes/no workflow: the agent checks official sources, presents a concrete event summary (title, dates, venue and any uncertainty), and asks only whether to publish it. After the user explicitly approves that exact event or an explicitly enumerated batch, the agent may perform the GitHub approval command on the user's behalf using the owner's connected account. Before executing, re-read the Issue and verify the presented fields and digest are unchanged. Record the user's decision and the approved fields/digest in an Issue audit comment, then submit the exact /approve command and verify Actions and the public site. A generic 'continue', a request to automate approval mechanics, silence, or a prior approval of different content is NOT approval of an event. If the user says no, record the decision and close the pending Issue without deleting history. If content changes, ask again. Never approve real events as tests, bypass ownership/digest checks, or publish without a specific human decision. Use /preview for live validation and temporary fixture data for positive tests. The user does not need to open GitHub, read JSON or enter approval codes.

Prefer official federation/organizer evidence. Separate uncertain dates and historical events. Do not invent future editions or event dates. Keep source errors and ambiguous records visible in the report.
