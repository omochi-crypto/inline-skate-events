# 練習会情報の調査と公開候補（2026-11-09追加）

利用者の依頼により、大会とは独立して一般参加できるインラインスケート練習会（スピード中心、他ジャンルも区別）を調査する。一般公開の定期練習、合同練習、体験練習は対象。主催者が会員限定とする活動、日時のない継続的な練習の存在、過去の練習報告、氷上競技だけの案内は掲載候補から除外する。参加条件が不明なチーム練習予定は「要問合せ・保留」とし、参加可能と断定しない。

確認項目は年付き日程と曜日、会場・都道府県、主催者、種目、外部参加の可否、費用、申込方法、公式根拠、雨天中止など。定期的な活動から個別開催を推定しない。大会・交流イベントとの重複をチェックし、参加条件が未確認のものを掲載しない。独立した練習会一覧ページと承認済みJSONを設け、実在案件の公開にはその練習会ごとの明示承認を必要とする。定期調査のGitHub書込や無断公開は行わない。既存のサイト負荷・取得制約、調査先の承認ルールを維持する。

# 交流イベントの別カテゴリー調査（2026-11-04追加）

利用者の依頼に基づき、ChatGPTの公開検索で「大会」と「交流イベント」を分けて収集・報告する。交流会、一般参加を募る合同滑走会・単発合同練習、フェス、デモイベント、単発の初心者・親子体験会を含む。一般公募のない通常練習、会員内の集まり、定期スクールのみは原則対象外。インライン以外の催事を混ぜない。

大会のスピード優先は維持する。交流イベントではインラインのジャンルを限定せず、内容・初心者可否・親子可否を示す。主催者の当該年資料で名称・開催日時・会場・内容・公開参加条件を確認する。費用・申込期限は確認値か未確認を示し、無料等を推測しない。曖昧な情報は保留し、既存の見送りを分類変更で再提案しない。

同じ催事に競技と交流企画がある場合は関連を示し二重計上を避ける。交流イベントの新規・既知・終了済み・保留・取得不可を大会と分けて記録する。詳細な条件と検索式は events/social-sources.json の community_events に記録する。

定期タスクは報告専用。未承認イベントの登録・公開はしない。これは公開検索・報告カテゴリーの追加であり、Actions抽出器やWebサイトへのカテゴリー追加はまだ行わない。公開する際には対応実装と個別の明示承認を要する。既存の負荷・取得制限を維持し、情報源や直接巡回を無断で増やさない。

# SNSによる大会情報の補完

公式サイトのGitHub Actions収集に加え、ChatGPTの定期タスク「SNSのインライン大会情報」が公開Web検索でSNSを補完調査します。

これはGitHub ActionsがSNSのタイムラインを直接取得する実装ではありません。X・Instagram・Facebookの全投稿の取得は保証しません。ログイン不要の公開情報・検索インデックスで見える投稿が対象です。初回調査ではFacebook上の大会関連発信を検索で確認できましたが、Facebook/Instagramのページ直接取得には失敗しています。定期タスクは設定済みですが、その初回自動実行の完了はまだ確認していません。

## 保存と承認

- 発信元の起点・公式性の根拠・取得制約は events/social-sources.json に記録。
- 投稿URLと主催者の公式募集要項で開催日・会場・種目を照合。
- 確認できる将来大会は標準の [大会候補] Issue として登録。情報不足は [SNS確認待ち] として別管理。
- 閉じたIssueと承認済み大会も含めて重複確認。過去の参加報告は新規掲載しない。
- 新しい候補は取得元リンク付きで利用者へ提示。利用者の「はい／いいえ」で判断し、承認されるまで公開しない。
- 新規候補・中止/日程変更などの重要な変更がなければ通知しない。取得エラーは候補ゼロと混同せず知らせる。

投稿の年月日と開催日を分けます。画像や年省略などで開催日が不明なら推測せず保留します。SNS転載や個人投稿だけを公式発表として扱いません。アカウントにログインしたり、非公開グループ・DMへアクセスしたり、SNSへ投稿する処理はありません。

## 2026-10-31: スピード中心の発見型調査方針

優先対象: インラインのトラック、ロード、マラソン、ウルトラ、地域記録会。氷上スピード、スラロームのタイム競技、練習会のみの告知は混同しない。その他種目の既存承認大会は維持する。

1. **既知ソース巡回**: 既存GitHub Actionsの公式サイト・地域サイト巡回は維持する（README記載の毎日10:25 JST）。
2. **横断発見**: 公開Web検索で大会名、地域、参加募集、記録会、主催者、チーム名、個人の公開投稿を探す。SNSの非公開投稿やログイン制限を回避しない。個人投稿は発見の手掛かりであり、公式要項の代わりではない。
3. **情報源発見**: 大会の主催クラブ、競技場、公園、継続的な発信者を情報源候補として記録し、公式性・公開範囲・収集可否を確認してから監視対象へ追加する。新たな自動スクレイパーは事前検証なしに増やさない。
4. **候補統合**: 大会名、開催日、会場、主催者で重複確認。閉じたIssueや見送り履歴、承認済みも参照する。日付不明・練習会・開催済みは公開候補にしない。
5. **人による承認**: 確認できた新規大会のみ提示し、明示承認まで公開しない。

推奨頻度は公開SNS横断検索を週2〜3回、情報源の新規探索を週1回、大会直前の変更確認を約1週間前とする。**これは運用設計上の推奨値であり、既存ChatGPT定期タスクの実行頻度を変更したことを意味しない。** 現在の定期タスクは従来どおり毎日検索する設定として記録されている。自動化の変更は別途タスク状態を確認して行う。

検索結果に氷上スピード競技が混入するため、インライン競技かどうかを本文・主催者・会場で検証する。公開個人アカウントの継続監視は必要性と公開範囲を慎重に判断する。

## 情報源キュレーションの承認フロー（2026-10-31）

- 定期調査では大会だけでなく、地域クラブ・主催者・スケート場・公開個人アカウントの**情報源候補**を発見する。
- 情報源候補には名称、公開URL、媒体、スピード競技との関連、過去の大会告知の証拠、発信頻度の確認可能な範囲、公式性・アクセス制限、重複、推奨理由を記録する。個人の私的情報は集めない。
- **採用推奨／保留／見送り**に分類し、根拠付きで数件まとめて利用者に提示する。既存の登録先と照合する。
- 利用者が情報源の追加を明示承認した場合だけ、公開情報の監視リストへの追加を行う。承認前は調査の一時的な手掛かりに限る。取得制限のあるSNSをスクレイピングしない。
- 情報源の採用は大会掲載の承認を意味しない。大会の公開は従来どおり大会ごとに明示承認を必要とする。
- 新規候補がない回は無理に提案しない。GitHubへの大量Issue登録・毎回の無意味な書き込みは避ける。
- 現時点ではキュレーション用の専用DBや自動採用処理は未実装。既存の定期調査タスクの報告で候補を整理し、承認後に人の指示に従って登録する。
